Message Flow
(1) QEMU guest starts
      |
      v
(2) sensor_sim generates telemetry sample
      |
      v
(3) sample sent to Rust collector
      |
      v
(4) Rust collector
    - receives message
    - validates schema
    - timestamps
    - logs/traces event
      |
      +------> ETW event on Windows
      |
      +------> structured Rust log
      |
      v
(5) normalized message forwarded to Python
      |
      v
(6) Python app
    - updates in-memory dataset
    - recalculates metrics
    - writes CSV / chart / UI update

Minimal first implementation sketch
This is the version I would build first.

Step 1:
QEMU guest simulator produces one JSON message per second

Step 2:
Rust collector listens on TCP localhost:9000

Step 3:
Rust collector validates message and appends host timestamp

Step 4:
Rust collector writes normalized JSONL to disk

Step 5:
Python app tails JSONL or reads periodic batches

Step 6:
Python app updates plots / metrics

No FFI yet. No bindings yet. No complicated protocol yet.
That keeps it teachable and debuggable.

Future expansion sketch
